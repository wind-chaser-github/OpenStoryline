# 问题清单与证据边界

所有路径相对本仓库。状态截至2026-10-15；未在本次文档交接中追加功能修复。

## I-01 多源粗剪覆盖文件／重复ID——已修复

- **证据**：原版一次粗剪输入多个源片段，共用目录，每个源片段从0命名；真实回复离线回放8记录只剩5文件。FFmpeg辅助函数允许覆盖。
- **修复**：`speech_rough_cut.py`将文件计数放到源片段循环之外，clip ID在结果内累计。
- **验证**：历史真实回放红绿验证；随仓库提供的离线回归使用实际节点/FFmpeg。
- **边界**：不涉及模型质量、对象数量、时间线版本、取消和跨运行幂等。最新一次自主运行没有调用粗剪，不能声称本轮实测再次覆盖该修复。

## I-02 官方筛选约束与精剪目标冲突——未修复，有真实调用证据

- **代码**：`prompts/tasks/filter_clips/zh/system.md`明确规定≤5段全保留，>5段保留严格超过80%，只有限去除相似镜头。
- **实际**：第23次模型请求确实包含两到三颗行星/45—70秒要求。原始回复对14段全部`keep=true`。是正常解析结果，非异常兜底。
- **推导**：14段至少保留12段，按实测时长最短12段仍有152.8秒。主Agent本次没有粗剪、直接建时间线，无法达到目标。
- **限制**：80%规则不是“所有官方路径一定失败”的证明；需要区分默认去重用途与内容精剪用途，不能笼统归咎模型。
- **证据**：[请求/回复摘录](evidence/filter-call.json)、[统计](evidence/latest-run.json)。

## I-03 ASR已识别，字幕没有进入成片——未修复，有数据与代码证据

- `local_asr`输出14段识别结果，但本次Agent未调用文案/字幕生成或粗剪。
- `plan_timeline_pro.py`常规分支读取`generate_script.group_scripts[].subtitle_units`；本轮默认`group_scripts=[]`，字幕轨0。
- 画面本身有章节与行星标签，但不是与解说对应的字幕。
- 下一步先验证已有官方技能的字幕能力与时间坐标；不能简单把完整ASR原时间戳粘到删减后的成片上。

## I-04 默认Agent的计划与实际调用不一致——待缩小原因

计划承诺选两到三颗行星和字幕；实际筛选全保留后仍分组渲染，没有根据结果发现目标未满足。本次选择通用workflow，但这不能证明“选错技能”是唯一原因：规则冲突、工具结果可见信息、字幕路径均独立存在。

应离线检查主Agent具体收到的工具摘要与可用历史读取工具，再决定是否需要最小结果反馈修复。不要凭印象改技能、换模型或反复追加指令。不同模型、不同技能路径的因果对照尚未完成。

## I-05 配置隔离缓存后Web预览403——未修复，属本地配置兼容问题

`agent_fastapi.py`的`SERVER_CACHE_DIR`固定为仓库`.storyline/.server_cache`；预览白名单没有读取本轮独立MCP缓存目录。因此文件存在、能本机解码，Web preview仍403。

下一轮优先在仓库默认缓存根下用新session隔离，不要移动旧文件假装下载通过。若确实要支持自定义目录，再为合法配置根增加最小补丁，并测路径穿越和越权；不能放开任意文件读取。这不是已证实的默认目录预览故障。

## I-06 取消后渲染仍落盘但未登记成功产物——已观察，未修复

发现语义失败后调用官方cancel，工具回传被取消；底层MoviePy随后完成缓存文件。正式render产物记录为0，历史保留取消状态。此行为不是文件丢失，也不能算成功成片历史通过。

需离线/本地测试取消时是否应该终止渲染、如何处理迟到完成与临时文件。尚未设计/实现恢复策略；不要重跑收费上游来补一次产物登记。

## I-07 成本计量与原版探测兼容——部分查清

- 官方粗剪逐句调用模型，长片可有70余次请求，每次携带上下文。主Agent和视觉理解也收费，不能只统计主Agent。
- 旧回合曾反复纠错并缺少完整usage；约55万是估算口径，不是经核验的完整账单。
- 最新一次27次调用132,805 tokens有逐次记录，另外两次验证请求不在回调内。
- 官方API验证`max_tokens=1`与此前某gpt-5.4网关响应不兼容；最新gpt-4.1可运行。历史把1改16的补丁已撤回，不据此断言模型普遍不可用。
- 后续统计需包含嵌套MCP sampling、凭证探测、失败/取消时在途请求；已报告token阈值不是绝对费用上限。

## I-08 旧选片/粗剪/时间线复用问题——历史假设，不是当前已解决能力

此前为避免旧结果串用加入过依赖追踪、版本校验与对象校验，并在其他位置增加字幕辅助逻辑；这些改动引入额外约束和失败，已全部撤回。当前没有可宣称通过的“变更选片后自动失效旧粗剪与旧时间线”保证。

伙伴应以独立离线用例验证：选片A→粗剪A→时间线A，再更新选片B；确认下游究竟读取哪个artifact、何时复用默认占位/历史结果。得到官方基线最小复现后再定补丁，不恢复整套旧校验代码。
